## ۲. الفبای امنیت به زبان یک کودک ۵ ساله (مفاهیم کلیدی)

> 🧒 **داستان این بخش:** فرض کن می‌خواهی وارد یک شهرک بازی بزرگ شوی. دم در، از تو بلیت می‌خواهند و چهره‌ات را با عکس شناسنامه‌ات مقایسه می‌کنند (**احراز هویت**). وقتی مطمئن شدند خودت هستی، یک مچ‌بند رنگی ضدآب به دستت می‌بندند (**توکن JWT**). حالا داخل شهرک بازی، برای سوار شدن به چرخ‌وفلک دیگر لازم نیست هر بار شناسنامه‌ات را نشان دهی؛ نگهبان فقط نگاهی به رنگ مچ‌بندت می‌اندازد! اگر مچ‌بند طلایی داشته باشی، اجازه ورود به اتاق بازی‌های ویژه را داری (**مجوزدهی ادمین**)، اما اگر مچ‌بندت آبی باشد فقط بازی‌های عادی را سوار می‌شوی.
> 
> **این بخش جواب می‌دهد:** تفاوت Authentication و Authorization چیست؟ چرا پسوردها چرخ‌گوشت می‌شوند و توکن JWT چطور کار می‌کند؟

---

### ۲.۱. کیستی؟ در برابر چه اجازه‌ای داری؟ (AuthN vs AuthZ)

دو کلمه شبیه به هم در دنیای مهندسی امنیت وجود دارد که هرگز نباید قاطی شوند:

| مفهوم | اصطلاح انگلیسی | تشبیه کودکانه | در پروژه سفیر |
|:---|:---|:---|:---|
| **احراز هویت (Authentication)** | AuthN | «تو واقعاً بهنام هستی؟ رمزم را می‌گویم تا باور کنی» | ثبت‌نام و ورود با شماره تماس و رمز عبور |
| **مجوزدهی (Authorization)** | AuthZ | «بهنام اجازه دارد سفارش شماره ۱۰۱ را لغو کند؟» | مشتری فقط سفارش خودش را می‌بیند، مدیر وضعیت را عوض می‌کند |

---

### ۲.۲. چرخ‌گوشت ریاضی: هش کردن رمز عبور (Password Hashing)

- **به زبان ۵ ساله:** فرض کن یک سیب، یک هویج و یک گردو را می‌ریزی توی چرخ‌گوشت و یک پوره درست می‌کنی. آیا با نگاه کردن به پوره می‌توانی هویج سالم را برگردانی بیرون؟ هرگز! اما اگر دوباره همان سیب و هویج را چرخ کنی، دقیقاً همان پوره به دست می‌آید.
- **به زبان فنی:** در پایگاه داده **هرگز نباید رمز عبور به صورت متن خام (Plaintext) ذخیره شود**. اگر هکری فایل دیتابیس را بردارد، رمز تمام کاربران لو می‌رود. با کتابخانه `bcrypt`، رمز با یک فرمول یک‌طرفه به یک رشته ۶۰ کاراکتری به نام **هش (Hash)** تبدیل می‌شود:
  - رمز خام: `secret123`
  - رشته هش‌شده در دیتابیس: `$2a$10$e8T8fOQGzMvK9...`
  - هیچ کامپیوتری در جهان نمی‌تواند از روی این رشته به کلمه `secret123` برگردد. موقع لاگین، رمز واردشده را دوباره چرخ می‌کنیم و پوره حاصل را مقایسه می‌کنیم!

---

### ۲.۳. مچ‌بند دیجیتال ضدجعل: ساختار توکن JWT

- **به زبان ۵ ساله:** چک بانکی را دیده‌ای؟ یک تکه کاغذ معمولی است، اما چون امضای برجسته و رسمی رئیس بانک پایش خورده، همه قبولش دارند. اگر کسی مبلغ چک را دستکاری کند، امضا باطل می‌شود!
- **به زبان فنی:** **JWT (JSON Web Token)** یک رشته متنی فشرده با سه بخش است که با نقطه (`.`) از هم جدا شده‌اند:

```text
[Header].[Payload].[Signature]
```

1. **سربرگ (Header):** نوع الگوریتم رمزنگاری (مثلاً `HS256`).
2. **بدنه اطلاعات (Payload):** هویت دارنده کارت (مثلاً `id: "c1"`, `role: "ADMIN"`). این اطلاعات باز و خواناست، اما...
3. **امضای محرمانه (Signature):** ترکیبی از هدر + پی‌لود که با یک کلید فوق‌محرمانه سرور امضا شده است. اگر کاربری نقش خود را از `CUSTOMER` به `ADMIN` تغییر دهد، امضای هش نامعتبر شده و سرور بلافاصله دستش را رو می‌کند!

---

### ۲.۴. نگهبان پیشخوان: مفهوم Middleware

- **به زبان ۵ ساله:** نگهبانی که دم درب اتاق عمل بیمارستان ایستاده است؛ اگر روپوش مخصوص نداشته باشی، اصلاً اجازه نمی‌دهد پایت را داخل اتاق بگذاری و همان دم در بیرونت می‌کند!
- **به زبان فنی:** تابعی در سرور که قبل از رسیدن درخواست به کنترلر اصلی اجرا می‌شود:
  1. هدر درخواست (`Authorization: Bearer <TOKEN>`) را می‌خواند.
  2. امضای JWT را راستی‌آزمایی می‌کند.
  3. اگر معتبر بود، اطلاعات کاربر را روی شیء `request.user` می‌گذارد و اجازه عبور می‌دهد.
  4. اگر معتبر نبود یا توکن وجود نداشت، بلافاصله پاسخ **`401 Unauthorized`** صادر می‌کند.

## ۳. ارتقای دیتابیس: اضافه کردن رمز و نقش کاربر

فایل `prisma/schema.prisma` در پروژه `C:\safir-project` را باز کن و مدل `Customer` را ارتقا بده:

```prisma
// prisma/schema.prisma — اضافه شدن رمز عبور و نقش به مدل کاربر

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

// نقش‌های مجاز در سیستم
enum Role {
  CUSTOMER  // مشتری عادی
  ADMIN     // مدیر پشتیبانی و عملیات
}

model Customer {
  id        String   @id @default(uuid())
  name      String
  phone     String   @unique
  password  String                        // رمز عبور هش‌شده با bcrypt
  role      Role     @default(CUSTOMER)   // نقش کاربر (پیش‌فرض مشتری عادی)
  createdAt DateTime @default(now())

  orders    Order[]
  messages  ChatMessage[]
}

model Order {
  id          String   @id @default(uuid())
  orderNumber String   @unique
  itemTitle   String
  status      String   @default("ثبت اولیه")
  city        String
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  customerId  String
  customer    Customer @relation(fields: [customerId], references: [id])
}

model ChatMessage {
  id        String   @id @default(uuid())
  sender    String
  content   String
  createdAt DateTime @default(now())

  customerId String?
  customer   Customer? @relation(fields: [customerId], references: [id])
}
```

حالا دستور مایگریشن را در ترمینال اجرا کن تا ستون‌های جدید در دیتابیس ایجاد شوند:
```powershell
npx prisma migrate dev --name add_auth_and_roles
```

## ۴. بازنویسی کامل سرور سفیر با گیت امنیتی (`server.js`)

فایل `server.js` در پروژه را با کدهای زیر جایگزین کن:

```javascript
// server.js — نسخه ۳: گام سوم (احراز هویت JWT و تفکیک نقش‌ها با Fastify و Prisma)

const fastify = require('fastify')({ logger: true });
const { PrismaClient } = require('@prisma/client');
const bcrypt = require('bcryptjs');

const prisma = new PrismaClient();

// ثبت پلاگین JWT با کلید محرمانه
fastify.register(require('@fastify/jwt'), {
  secret: 'SAFIR_SUPER_SECRET_KEY_2026_OFFLINE_SECURE' // در پروداکشن از env خوانده می‌شود
});

// ۱. هوک کمکی نگهبان: اعتبارسنجی لاگین بودن کاربر
fastify.decorate('authenticate', async function (request, reply) {
  try {
    await request.jwtVerify(); // بررسی امضا و استخراج request.user
  } catch (err) {
    reply.status(401);
    return reply.send({ success: false, error: 'برای دسترسی به این بخش باید ابتدا لاگین کنی!' });
  }
});

// ۲. هوک کمکی نگهبان: بررسی دسترسی ادمین
fastify.decorate('requireAdmin', async function (request, reply) {
  if (!request.user || request.user.role !== 'ADMIN') {
    reply.status(403); // Forbidden
    return reply.send({ success: false, error: 'فقط مدیران سیستم (ADMIN) اجازه انجام این عملیات را دارند!' });
  }
});

// ── مسیرهای احراز هویت (Auth Endpoints) ──

// ثبت‌نام کاربر جدید با رمز عبور چرخ‌گوشت‌شده
fastify.post('/api/auth/register', async (request, reply) => {
  const { name, phone, password, role } = request.body || {};

  if (!phone || !password || password.length < 6) {
    reply.status(400);
    return { success: false, error: 'شماره تماس و رمز عبور (دست‌کم ۶ کاراکتر) الزامی است.' };
  }

  try {
    // هش کردن رمز عبور (۱۰ دور سالت استاندارد)
    const hashedPassword = await bcrypt.hash(password, 10);

    const customer = await prisma.customer.create({
      data: {
        name: name || 'کاربر جدید',
        phone,
        password: hashedPassword,
        role: role === 'ADMIN' ? 'ADMIN' : 'CUSTOMER'
      }
    });

    reply.status(201);
    return {
      success: true,
      message: 'ثبت‌نام با موفقیت انجام شد.',
      user: { id: customer.id, name: customer.name, phone: customer.phone, role: customer.role }
    };
  } catch (err) {
    if (err.code === 'P2002') {
      reply.status(409);
      return { success: false, error: 'این شماره تماس قبلاً در سامانه ثبت شده است!' };
    }
    reply.status(500);
    return { success: false, error: 'خطای سرور در ثبت‌نام' };
  }
});

// ورود به سیستم و صدور مچ‌بند دیجیتال (JWT Token)
fastify.post('/api/auth/login', async (request, reply) => {
  const { phone, password } = request.body || {};

  if (!phone || !password) {
    reply.status(400);
    return { success: false, error: 'شماره تماس و رمز عبور را وارد کنید.' };
  }

  const user = await prisma.customer.findUnique({ where: { phone } });
  if (!user) {
    reply.status(401);
    return { success: false, error: 'شماره تماس یا رمز عبور اشتباه است!' };
  }

  // بررسی تطابق رمز ورودی با هش دیتابیس
  const isValid = await bcrypt.compare(password, user.password);
  if (!isValid) {
    reply.status(401);
    return { success: false, error: 'شماره تماس یا رمز عبور اشتباه است!' };
  }

  // صدور توکن معتبر با پی‌لود هویت
  const token = fastify.jwt.sign({
    id: user.id,
    phone: user.phone,
    name: user.name,
    role: user.role
  });

  return {
    success: true,
    token,
    user: { id: user.id, name: user.name, phone: user.phone, role: user.role }
  };
});

// مشاهده پروفایل کاربر جاری (نیازمند توکن در هدر)
fastify.get('/api/auth/me', { preHandler: [fastify.authenticate] }, async (request, reply) => {
  return {
    success: true,
    authenticatedUser: request.user
  };
});

// ── مسیر چت امن (تنها کاربران لاگین‌شده می‌توانند پیام دهند) ──
fastify.post('/api/chat', { preHandler: [fastify.authenticate] }, async (request, reply) => {
  const { message } = request.body || {};
  if (!message || message.trim() === '') {
    reply.status(400);
    return { success: false, error: 'متن پیام نمی‌تواند خالی باشد!' };
  }

  const currentUser = request.user; // استخراج‌شده مستقیم از توکن JWT!

  // ثبت پیام در دیتابیس متصل به آیدی واقعی کاربر
  const savedMsg = await prisma.chatMessage.create({
    data: { sender: 'کاربر', content: message.trim(), customerId: currentUser.id }
  });

  const botReply = `درود ${currentUser.name}! هویت شما با مچ‌بند JWT تأیید شد. پیامت در دیتابیس ثبت گردید.`;
  await prisma.chatMessage.create({
    data: { sender: 'سفیر (سیستم)', content: botReply, customerId: currentUser.id }
  });

  return { success: true, reply: botReply, messageId: savedMsg.id };
});

// ── تغییر وضعیت سفارش (فقط ادمین‌ها اجازه دارند!) ──
fastify.patch(
  '/api/orders/:orderNumber/status',
  { preHandler: [fastify.authenticate, fastify.requireAdmin] },
  async (request, reply) => {
    const { orderNumber } = request.params;
    const { status } = request.body || {};

    if (!status) {
      reply.status(400);
      return { success: false, error: 'وضعیت جدید سفارش را مشخص کنید.' };
    }

    try {
      const updatedOrder = await prisma.order.update({
        where: { orderNumber: String(orderNumber) },
        data: { status }
      });

      return {
        success: true,
        message: `وضعیت سفارش ${orderNumber} توسط مدیر به «${status}» تغییر یافت.`,
        order: updatedOrder
      };
    } catch (err) {
      reply.status(404);
      return { success: false, error: `سفارشی با شماره ${orderNumber} پیدا نشد!` };
    }
  }
);

// روشن کردن سرور
fastify.listen({ port: 3000, host: '0.0.0.0' }).then(addr => {
  console.log(`\n🛡️ سرور سفیر همراه با گیت نگهبانی JWT روی ${addr} آغاز به کار کرد!\n`);
});
```

## ۵. تست‌های زنده در Bruno و راستی‌آزمایی امنیت

> 🧒 **داستان این بخش:** اینجا آزمایش دزد و پلیس است! سعی می‌کنیم بدون کارت وارد شویم تا ببینیم نگهبان چطور جلوی ما را می‌گیرد، و بعد با کارت مشتری عادی تلاش می‌کنیم وارد اتاق مدیر شویم تا خطای ۴۰۳ را با چشم ببینیم.
> 
> **این بخش جواب می‌دهد:** چطور توکن JWT را بگیریم و در هدر Authorization ارسال کنیم؟

### تست ۱: ثبت‌نام کاربر مدیر (`POST /api/auth/register`)
- **آدرس:** `http://localhost:3000/api/auth/register`
- **بدنه JSON:**
```json
{
  "name": "مدیر سیستم سفیر",
  "phone": "09129990000",
  "password": "adminSecret123",
  "role": "ADMIN"
}
```
- **پاسخ سرور:** `201 Created`

## ۶. 🧗 تمرین‌های چریکی و ارتقای امنیت

### تمرین اول: انقضای توکن (Token Expiry)
در فایل `server.js` هنگام ساین کردن توکن، مدت اعتبار ۱ ساعته بگذار:
```javascript
const token = fastify.jwt.sign(payload, { expiresIn: '1h' });
```
تست کن که آیا بعد از گذشت زمان توکن منقضی می‌شود یا نه.

### تمرین دوم: محافظت در برابر سرقت هویت (IDOR Guard)
در روت مشاهده سفارشات (`GET /api/orders/:orderNumber`) کاری کن که مشتری فقط بتواند سفارشاتی را ببیند که `customerId` آن‌ها برابر با `request.user.id` باشد؛ مگر اینکه نقش کاربر `ADMIN` باشد!
