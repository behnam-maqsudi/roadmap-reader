## ۲. الفبای وب به زبان یک کودک ۵ ساله (مفاهیم کلیدی)

> 🧒 **داستان این بخش:** فرض کن توی یک رستوران بزرگ نشسته‌ای. تو گرسنه‌ای و یک پیتزا می‌خواهی. آیا خودت اجازه داری بدوی توی آشپزخانه و دستت را بکنی توی قابلمه‌ها؟ معلوم است که نه! تو روی صندلی می‌نشینی، گارسون می‌آید، دفترچه‌اش را درمی‌آورد، سفارش تو را با علامت‌های مشخص می‌نویسد، می‌برد داخل آشپزخانه و چند دقیقه بعد، بشقاب غذا را می‌گذارد جلوی تو. اگر پیتزا تمام شده باشد هم با احترام می‌گوید «شرمنده، نداریم!». اینترنت و وب‌سرور دقیقاً همین رستوران است.
> 
> **این بخش جواب می‌دهد:** کلاینت، سرور، پورت، HTTP و JSON دقیقاً در دنیای واقعی چه هستند و چرا به آن‌ها نیاز داریم؟

### ۲.۱. مشتری و آشپزخانه (Client & Server)

- **به زبان ۵ ساله:** مشتری (کلاینت) تویی که تقاضا می‌کنی؛ آشپزخانه (سرور) آنجایی است که سفارش را می‌پزد و تحویل می‌دهد.
- **به زبان فنی:**
  - **کلاینت (Client):** برنامه‌ای که درخواست اطلاعات را آغاز می‌کند (مثل مرورگر فایرفاکس/کروم، اپلیکیشن موبایل، یا ابزار Bruno).
  - **سرور (Server):** کامپیوتری که همیشه روشن است، به یک شبکه وصل است و یک نرم‌افزار روی آن در حال گوش دادن به درخواست‌های رسیده است تا پردازش کرده و پاسخ بفرستد.

```text
  [ کلاینت / مشتری ]  ========== (درخواست / Request) ==========>  [ سرور / آشپزخانه ]
  (Bruno یا موبایل)  <========== (پاسخ / Response) <==========   (کد Fastify ما)
```

---

### ۲.۲. آدرس خیابان و شماره واحد (IP Address & Port)

- **به زبان ۵ ساله:** فرض کن در یک برج ۱۰۰ واحدی زندگی می‌کنی. نام خیابان و پلاک ساختمان مشخص می‌کند کدام ساختمان است (IP). اما پستچی باید بداند بسته را دم درب کدام واحد تحویل دهد (Port)!
- **به زبان فنی:**
  - **آدرس IP:** شناسه یکتای عددی دستگاه شما در شبکه (مثلاً `127.0.0.1` که یعنی «همین کامپیوتر خودم» یا به زبان دیگر `localhost`).
  - **شماره پورت (Port):** یک عدد بین ۱ تا ۶۵۵۳۵ روی سیستم‌عامل که مشخص می‌کند داده به کدام برنامه تحویل داده شود. مثلاً وب‌سرور محلی پروژه سفیر روی پورت `3000` گوش می‌دهد. بنابراین آدرس کامل می‌شود:
    `http://127.0.0.1:3000` یا `http://localhost:3000`

### ۲.۳. کارهای مجاز با منو: متدهای HTTP (Methods)

وقتی به گارسون پیام می‌دهی، نوع خواسته‌ات فرق دارد:

| متد HTTP | تشبیه کودکانه | کار مهندسی در پروژه | مثال واقعی |
|:---|:---|:---|:---|
| **GET** | «لطفاً منوی امروز را نشانم بده» (فقط دیدن و خواندن) | گرفتن اطلاعات بدون تغییر دادن چیزی در سرور | دیدن وضعیت سفارش: `GET /api/orders/102` |
| **POST** | «این برگه را بگیر و این غذای جدید را برایم ثبت کن» | فرستادن اطلاعات تازه به سرور برای پردازش و ذخیره | ارسال پیام در چت: `POST /api/chat` |
| **PUT / PATCH** | «سفارشم را عوض کن، به جای نوشابه دوغ بگذار» | ویرایش و تغییر اطلاعات موجود در سرور | تغییر آدرس گیرنده سفارش |
| **DELETE** | «سفارشم را کلاً لغو کن و خط بزن» | حذف یک موجودیت از سیستم | پاک کردن تیکت یا پیام |

### ۲.۴. زبان مشترک: فرمت JSON

- **به زبان ۵ ساله:** اگر مشتری چینی صحبت کند و آشپز فرانسوی، هیچ غذایی آماده نمی‌شود! باید یک فرم سفارش ساده و بین‌المللی با خط خوانا داشته باشند.
- **به زبان فنی:** فرمت **JSON** (مخفف JavaScript Object Notation) یک قالب استاندارد متنی ساده به صورت کلید و مقدار (Key-Value) است که همه زبان‌های برنامه‌نویسی و سیستم‌ها آن را می‌فهمند:

```json
{
  "sender": "کاربر",
  "message": "سلام، بسته پستی من کجاست؟",
  "orderId": 4082
}
```

### ۲.۵. کدهای وضعیت (Status Codes): کارت‌های پیام گارسون

سرور نمی‌تواند با جملات طولانی جواب دهد؛ ابتدا یک عدد سه رقمی استاندارد اعلام می‌کند:

- **خانواده ۲۰۰ (سبز - همه‌چیز روبه‌راه است):**
  - `200 OK`: درخواست انجام شد و نتیجه خدمت شما!
  - `201 Created`: مورد جدید با موفقیت ساخته و ذخیره شد.
- **خانواده ۴۰۰ (نارنجی - اشتباه از طرف مشتری است):**
  - `400 Bad Request`: نامه‌ات ناقص است (مثلاً پیام خالی فرستادی!).
  - `404 Not Found`: غذایی یا آدرسی که خواستی پیدا نشد (مثلاً سفارشی با این شماره نداریم).
- **خانواده ۵۰۰ (قرمز - دیگ آشپزخانه ترکیده!):**
  - `500 Internal Server Error`: کد سرور باگ خورده یا کرش کرده است.

### ۲.۶. چرا فریم‌ورک Fastify؟

در دنیای Node.js، فریم‌ورک معروفی به نام Express وجود دارد که در سال ۲۰۱۰ ساخته شد. اما Fastify در سال‌های اخیر اختراع شد چون:
1. **سرعت پردازش تا ۴ برابر بالاتر:** برای سیستم‌های هوش مصنوعی و چت زنده حیاتی است.
2. **ساپورت عالی از ساختار JSON:** تبدیل خودکار آبجکت‌ها بدون نیاز به کتابخانه‌های اضافی.
3. **لاگینگ توکار و زیبا:** خودش به شکل رنگی تمام رفت‌وآمد درخواست‌ها را گزارش می‌دهد.

### گام ۳: نوشتن اولین سرور زنده (`server.js`)

در پوشه `C:\safir-project` فایلی به نام `server.js` بساز و کدهای زیر را در آن کپی کن:

```javascript
// server.js — سنگ‌بنای پروژه سفیر (نسخه ۳: گام اول)

// ۱. فراخوانی فریم‌ورک Fastify همراه با فعال‌سازی لاگر رنگی
const fastify = require('fastify')({
  logger: true // تمام درخواست‌های رسیده را در ترمینال چاپ می‌کند
});

// ۲. مسیر تست سلامت (Health Check): آیا سرور بیدار است؟
fastify.get('/health', async (request, reply) => {
  return {
    status: 'healthy',
    service: 'Safir Core Assistant',
    uptime: process.uptime(),
    timestamp: new Date().toISOString()
  };
});

// ۳. مسیر دریافت پیام چت از مشتری (Chat Endpoint)
fastify.post('/api/chat', async (request, reply) => {
  const body = request.body;

  // اعتبارسنجی ساده: آیا پیامی ارسال شده است؟
  if (!body || !body.message || body.message.trim() === '') {
    reply.status(400); // خطای اشتباه مشتری
    return {
      success: false,
      error: 'متن پیام نمی‌تواند خالی باشد!'
    };
  }

  const userMessage = body.message;
  const userName = body.name || 'کاربر گرامی';

  // در این فاز پاسخ تلفنچی شبیه‌سازی می‌شود تا بعداً در فاز ۵ به مغز LLM وصل شود
  const botReply = `درود ${userName}! پیام شما («${userMessage}») در سامانه سفیر دریافت شد. هم‌اکنون در حال بررسی درخواستت هستم.`;

  return {
    success: true,
    reply: botReply,
    receivedAt: new Date().toISOString()
  };
});

// ۴. مسیر استعلام وضعیت سفارش بر اساس شماره (GET with URL Parameter)
fastify.get('/api/orders/:id', async (request, reply) => {
  const orderId = request.params.id;

  // دیتابیس ساختگی موقت برای تمرین فاز اول
  const fakeDatabase = {
    '101': { item: 'هدفون گیمینگ', status: 'تحویل پست داده شد', city: 'تهران' },
    '102': { item: 'کتاب طراحی سیستم', status: 'در حال بسته‌بندی در انبار', city: 'اصفهان' },
    '103': { item: 'ماگ سفالی برنامه‌نویسی', status: 'تحویل داده شده به خریدار', city: 'شیراز' }
  };

  const foundOrder = fakeDatabase[orderId];

  if (!foundOrder) {
    reply.status(404);
    return {
      success: false,
      error: `سفارشی با شناسه ${orderId} پیدا نشد!`
    };
  }

  return {
    success: true,
    orderId: orderId,
    details: foundOrder
  };
});

// ۵. روشن کردن موتور سرور روی پورت ۳۰۰۰
const startServer = async () => {
  try {
    const address = await fastify.listen({ port: 3000, host: '0.0.0.0' });
    console.log(`\n🚀 سرور سفیر با موفقیت روی آدرس ${address} به پرواز درآمد!\n`);
  } catch (err) {
    fastify.log.error(err);
    process.exit(1);
  }
};

startServer();
```

### تست ۱: بررسی نبض سرور (`GET /health`)

1. برنامه **Bruno** را باز کن.
2. روی دکمه **Create Collection** کلیک کن و نام آن را `Safir-Phase1` بگذار و یک پوشه در کامپیوترت برای آن انتخاب کن.
3. روی علامت سه‌نقطه یا دکمه **New Request** کلیک کن:
   - **Name:** `Health Check`
   - **Type:** `HTTP`
   - **Method:** `GET`
   - **URL:** `http://localhost:3000/health`
4. دکمه بنفش‌رنگ **Send** (یا کلیدهای میانبر `Ctrl + Enter`) را بزن.

#### خروجی مورد انتظار در پنل پاسخ (Response):
- **Status:** `200 OK`
- **Body:**
```json
{
  "status": "healthy",
  "service": "Safir Core Assistant",
  "uptime": 14.52189,
  "timestamp": "2026-10-15T00:15:00.000Z"
}
```

### تست ۲: ارسال پیام چت به دستیار سفیر (`POST /api/chat`)

1. در کالکشن برونو، یک ریکوئست جدید بساز:
   - **Name:** `Send Message`
   - **Method:** `POST`
   - **URL:** `http://localhost:3000/api/chat`
2. به تب **Body** در زیر آدرس برو، حالت را روی **JSON** بگذار و این متن را بنویس:
```json
{
  "name": "بهنام",
  "message": "سلام سفیر! وضعیت بسته‌ام رو چک کن"
}
```
3. دکمه **Send** را بزن.

#### خروجی مورد انتظار:
- **Status:** `200 OK`
- **Body:**
```json
{
  "success": true,
  "reply": "درود بهنام! پیام شما («سلام سفیر! وضعیت بسته‌ام رو چک کن») در سامانه سفیر دریافت شد. هم‌اکنون در حال بررسی درخواستت هستم.",
  "receivedAt": "2026-10-15T00:16:12.123Z"
}
```

## ۵. 🧗 تمرین‌های تثبیت مهارت (دست‌به‌آچار شدن چریکی)

برای اینکه مطمئن شوی مفاهیم در ذهنت حک شده‌اند و فردا در شرایط آفلاین بتوانی بدون نگاه کردن به کد بنویسی، این ۳ تمرین را خودت در `server.js` پیاده کن:

### تمرین اول: ثبت درخواست لغو سفارش (`POST /api/orders/:id/cancel`)
یک روت جدید اضافه کن که شماره سفارش را از آدرس (پارامتر URL) بگیرد، دلیل لغو را از Body در قالب JSON با کلید `reason` دریافت کند:
- اگر شماره سفارش در `fakeDatabase` نبود، خطای ۴۰۴ بدهد.
- اگر بود، فیلد `status` آن را به `"لغو شده"` تغییر دهد و پاسخی با پیام زیر برگرداند:
  ```json
  {
    "success": true,
    "message": "سفارش 101 به دلیل «انصراف از خرید» لغو گردید."
  }
  ```

### تمرین دوم: لیست تمام سفارشات (`GET /api/orders`)
روتی بنویس که کل آبجکت `fakeDatabase` و تعداد کل سفارشات ثبت‌شده را به کاربر برگرداند:
```json
{
  "success": true,
  "total": 3,
  "orders": { ... }
}
```

### تمرین سوم: شبیه‌سازی اپراتور با پاسخ‌های متنوع
در مسیر `POST /api/chat`، آرایه‌ای از ۳ پاسخ پیش‌فرض بساز:
```javascript
const defaultAnswers = [
  "پیام شما به واحد پشتیبانی ارجاع شد.",
  "سفیر در حال بررسی درخواست شما در پایگاه انبار است.",
  "از شکیبایی شما سپاسگزاریم، نتیجه به زودی ارسال می‌شود."
];
```
با استفاده از تابع `Math.random()` هر بار یکی از این جملات را تصادفی انتخاب کن و به انتهای پاسخ اضافه کن.
