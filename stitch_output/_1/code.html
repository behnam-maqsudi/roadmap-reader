شنیدن پادکست معماری 06:20

در طراحی سامانه‌های مدرن، گذر از معماری یکپارچه (Monolith) به معماری توزیع‌شده مبتنی بر میکروسرویس‌ها، چالش‌های بنیادینی در حفظ یکپارچگی داده و هماهنگی وضعیت به وجود می‌آورد. هنگامی که مرزهای پایگاه داده در سطح سرویس‌ها تفکیک می‌شوند، بهره‌گیری از تراکنش‌های سنتی مبتنی بر قفل‌های توزیع‌شده (Two-Phase Commit / 2PC) به علت ایجاد گلوگاه‌های مسدودکننده (Blocking) و آسیب‌پذیری شدید در برابر خطاهای شبکه، رویکردی ضدالگو به شمار می‌آید.

hub ارکستریشن رویدادها (Orchestration)

یک هماهنگ‌کننده مرکزی (Orchestrator یا State Machine) توالی فراخوانی سرویس‌ها را کنترل و مدیریت جبران خسارت خطاها را دقیقاً دیکته می‌کند؛ مناسب برای جریان‌های کاری پیچیده مالی و بانکی با وضعیت‌های چندمرحله‌ای.

all_inclusive رقص رویدادها (Choreography)

سرویس‌ها بدون اطلاع از وجود یکدیگر، رویدادهای دامنه خود را در پیام‌رسان توزیع‌شده منتشر کرده و نسبت به رویدادهای دیگر واکنش نشان می‌دهند؛ ایجاد حداکثر استقلال، جداسازی و مقیاس‌پذیری افقی.

نکته کلیدی معماری: تفکر همزمانی نهایی

در سیستم‌های رویدادمحور با توان گذردهی بالا، مفهوم Eventual Consistency (همزمانی نهایی) جایگزین تراکنش‌های اسیدی سفت‌وسخت می‌شود. برای مدیریت خطا و عدم مغایرت مالی، پیاده‌سازی الگوی Saga با تراکنش‌های جبران‌کننده (Compensating Transactions) ضرورت حتمی دارد.

پیاده‌سازی الگوی Outbox و تضمین At-Least-Once Delivery

یکی از مخاطرات عمده در معماری مبتنی بر پیام، وضعیت Dual-Write Problem است؛ زمانی که پایگاه‌داده محلی سرویس بروزرسانی می‌شود اما انتشار پیام در آپاچی کافکا به دلیل نوسانات شبکه با شکست مواجه می‌گردد. الگوی Transactional Outbox با ذخیره رکورد رویداد در یک جدول اختصاصی به نام outbox_events تحت همان تراکنش پایگاه داده اصلی، پایایی پیام را صددرصد تضمین می‌کند.

package outbox

import (
    "context"
    "database/sql"
    "encoding/json"
    "github.com/google/uuid"
)

// PersistOrderWithOutbox creates the domain record and the outbox event atomically
func (s *OrderService) CreateOrderTransactional(ctx context.Context, order *Order) error {
    tx, err := s.db.BeginTx(ctx, &sql.TxOptions{Isolation: sql.LevelReadCommitted})
    if err != nil { return err }
    defer tx.Rollback()

    // ۱. درج اطلاعات سفارش در جدول اختصاصی
    if err := s.insertOrder(ctx, tx, order); err != nil { return err }

    // ۲. ایجاد رکورد رویداد در جدول Outbox برای پردازش CDC توسط Debezium
    eventPayload, _ := json.Marshal(order)
    outboxQuery := `INSERT INTO outbox_events (id, aggregate_type, payload, status) VALUES ($1, $2, $3, 'PENDING')`
    if _, err := tx.ExecContext(ctx, outboxQuery, uuid.NewString(), "ORDER_CREATED", eventPayload); err != nil {
        return err
    }

    return tx.Commit() // تضمین عدم بروز ناسازگاری داده‌ای
}
