# راهنمای نوشتن داستان — برای کارگرهای فرعی

این فایل را **کامل بخوان**. قالبش را رعایت کن، وگرنه متن یکدست نمی‌شود.

## چرا داشتیم

متن قبلی «تیتر وار» بود: خواننده می‌دید `## ۱. جعبه‌ابزار بیلد` و هیچ‌چیز
نمی‌فهمید — این مبحث از کجا آمد، چرا وجود دارد، به کجا می‌رسد. حالا هر بخش با
یک **داستان** شروع می‌شود که آن سه سؤال را جواب می‌دهد.

## قالب دقیق

### ۱. داستانِ کل فاز

بلافاصله بعد از خط عنوان (`# فاز ۲ — ...`). فقط برای **یک فاز**.

```json
"phase": [
  "",
  "> 🧒 **داستان:** سال ۲۰۰۹، یک نفر به اسم **رایان دال** ...",
  "> ...",
  "",
  "> ...",
  "> ..."
]
```

ساختار روایت (چهار تکه، به همین ترتیب):
1. **صحنه‌ی واقعی** — یک لحظه‌ی مشخص. چه کسی، چه زمانی، چه چیزی خراب بود.
2. **راه‌حلِ بد** — آن روزها چه می‌کردند و چرا جواب نمی‌داد. **اینجا** سؤال
   «چرا اصلاً این مبحث هست» جواب داده می‌شود.
3. **اختراع** — چه کسی، چه سالی، چه فکری.
4. **حصربه‌گیری** — این فاز کدام تکه را حل می‌کند.

### ۲. نقشه‌ی فاز

قبل از `## مقدمه`. یک جدول: `# | بخش | مسئله‌ای که حل می‌کند | کجا می‌آید`.

```json
"map": [
  "## 🗺️ نقشه‌ی این فاز",
  "",
  "| # | بخش | مسئله‌ای که حل می‌کند | کجا می‌آید |",
  "|---|------|-------------------|-----------|",
  "| ۱ | ... | ... | ... |",
  "",
  "> 💡 ترتیب بخش‌ها مهم است: ...",
  ""
]
```

ستون آخر حیاتی است: نشان می‌دهد این بخش کجای زندگیِ واقعی به کار می‌آید.

### ۳. داستانِ هر بخش

بلافاصله بعد از تیتر `## N.`:

```json
{
  "heading": "## ۱. جعبه‌ابزار بیلد و اجرای تایپ‌اسکریپت",
  "text": [
    "",
    "> 🧒 **داستان این بخش:** ...",
    "> ...",
    "",
    "> ...",
    "> **این بخش جواب می‌دهد:** ..."
  ]
}
```

آخرین خط باید بگوید **این بخش دقیقاً چه چیزی را جواب می‌دهد**. بدون آن،
خواننده نمی‌فهمد چرا این قسمت را باید بخواند.

## قوانین سخت

| قاعده | چرا |
|---|---|
| فقط `>` و متن. جدول و کد داخل بلوکِ `>` مجاز است ولی کم. | استایلِ مخصوص دارد |
| **۲ تا ۵ سطر** در هر بخش. بیشتر از ۵ یعنی مقدمه شده. | متن نباید سنگین شود |
| هر جمله **حدود ۱۵ کلمه**. | خواندنِ راحت |
| **عدد و اسم واقعی**: سال، نسخه، نام آدم، تعداد، هزینه. | داستانِ بدون جزئیات، قصه نیست |
| هر اصطلاح تازه را **در خودِ داستان** تعریف کن | خواننده هنوز به تعریف نرسیده |
| **غلط تاریخی نکن.** اگر مطمئن نیستی، بنویس «حدوداً» یا حذفش کن. | بهتر از دروغ |
| از `arch` و متن‌های قاطی انگلیسی‌-فارسی پرهیز کن | «این کarchیتکتوری» اشتباه شد |
| امنیت: دفاعی/آموزشی. هرگز حمله به سیستم واقعی. | قاعده‌ی ثابت پروژه |
| داده‌ی نمونه: ساختگی. دامنه‌ی `.test`، بدون داده‌ی کسی واقعی. | قاعده‌ی ثابت پروژه |

## چطور چیزی را سر جایش بگذاری

فایل `ابزار/داستان‌ها.json` را باز کن و کلیدِ فایلت را پیدا کن.

- `heading` را **دقیقاً** از فایل کپی کن (شامل `## ` و شماره‌ی فارسی).
- توابع `node ابزار/درج-داستان.mjs` با متن تیتر پیدا می‌کند، پس حتی اگر خط‌ها
  جابه‌جا شده باشی کار می‌کند.
- بعد از نوشتن، `node ابزار/بازبینی-متن.mjs` را اجرا کن.

## چطور چیزی را راستی‌آزمایی کنی

`WebSearch` و `WebFetch` را داری. **هر عدد و اسمی را که می‌نویسی راستی‌آزمایی کن.**

پژوهش را موازی انجام بده (چند `Agent` با `subagent_type: Explore`). برای هر
ادعای تاریخی منبع پیدا کن. اگر چیزی را قطعی ندانستی، در متن ننویس.

## ترتیب کار

1. اول `WebSearch` — تاریخچه‌ی ابزارهای آن فاز را راستی‌آزمایی کن.
2. بعد JSON را بنویس (فازها به ترتیب: `فاز-۰۰-…` تا `فاز-۱۳-…`).
3. `node ابزار/درج-داستان.mjs`
4. `node ابزار/بازبینی-متن.mjs` — باید برای فازِ تو تمیز باشد.
